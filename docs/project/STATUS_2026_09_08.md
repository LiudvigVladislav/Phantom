## What the local work establishes

- **Text completion and held delivery:** host compositions exercise atomic
  text/receive-state/completion persistence, pending-session and exact OPK
  binding, no ACK before durable completion, transport parking without ACK,
  and owned local replay. File-reopen tests are not process-kill experiments.
  The original source of delivery inversion remains unidentified.
- **Displaced receive sessions:** the candidate retains displaced states
  encrypted with a 24-hour eligibility window after displacement for late text.
  Expired state is ineligible before cleanup; deletion waits for an owned cleanup
  pass if the application is stopped. The clock and storage-erasure limits remain.
  This deliberately extends retention; it is not reconstruction of erased state,
  unlimited history, a skipped-message-key cache or relaxed MAC verification.
- **Background recovery:** one named envelope was persisted after unlock and
  before USB reattachment. That establishes USB-independent recovery for that
  observation, not timely delivery while locked or a complete background pass.
  Earlier locked-device startup crashes led to a separate guarded-startup fix.
- **Locked startup:** the candidate gates access on unlock/readiness and retains
  focused host verification. A short warm-process lock check is not a cold-start
  hardware-Keystore acceptance or long unplugged qualification.
- **Unread and connection presentation:** selected device checks showed the
  unread count clearing after reading and idle-only protective fallback retaining
  `Online Limited realtime`. This does not prove the WSS channel healthy.
- **Message notifications:** explicit opt-in produced a visible message
  notification separate from the persistent service-status notification.
  Subsequent tapping opened the correct chat. This is a named device observation,
  not coverage of all permission, sound, vibration, OEM or background cases.
