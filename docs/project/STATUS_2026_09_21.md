# PHANTOM status - 2026-09-21

This is a point-in-time reconciliation of the public planning documents with
`master` at `88bf5edab1253ff799a106e9ab6b27e3c33eda08`.

## Shipped on master

- PR #410 published the investor-facing project and funding material.
- PR #411 made outbound recovery fail closed: queued ciphertext is replayed in
  deterministic order and every production encryption entry path settles the
  existing conversation state first.
- PR #412 added Android 16 KiB native page-size support.
- PR #413 completed the API 36 release baseline, fail-closed production
  signing, atomic archived-session control events, and honest realtime recovery
  wording.
- A signed APK and AAB were validated locally. The APK was installed from a
  clean state on a physical Android 12 phone and an API 37 / 16 KiB emulator;
  bidirectional text and read receipts passed.

## In progress

- Android design parity is being completed in a separate worktree. It is not
  part of this snapshot and is not claimed complete here.
- Production relay rotation remains operational work. Durable queue persistence
  was merged in PR #397, but the currently running production image was built
  before that merge. Restart safety is therefore a deployment property still to
  be closed, not merely a source-code property.

## Presentation-candidate gates

1. Integrate the design work without weakening the release baseline.
2. Deploy and prove restart recovery of the durable relay queue; remove the
   completed heartbeat-echo diagnostic flag.
3. Run the expanded two-device smoke for voice, privacy-mode switching,
   network/process recovery, and the supported call surface.
4. Build and verify the final signed APK/AAB, clean-install both targets, and
   rehearse the exact video path.

## Honest boundaries

- The current release surface is 1:1 text and voice notes. Groups and calls are
  not represented as production-ready.
- Tor remains text-only.
- The custom protocol composition has not received an independent external
  cryptographic audit.
- Passing tests and two-device field runs establish the named configurations
  and dates, not every Android device, carrier, or future filtering policy.
