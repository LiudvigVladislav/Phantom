# PHANTOM status - 2026-09-22

This is a point-in-time reconciliation of the public planning documents with
`master` at `73e24d3c82cce6a43cebe0f664d85d0e6c9e082e`.

## Shipped on master

- PR #411 made outbound recovery fail closed: queued ciphertext is replayed in
  deterministic order and every production encryption entry path settles the
  existing conversation state first.
- PR #412 added Android 16 KiB native page-size support.
- PR #413 completed the API 36 release baseline, fail-closed production
  signing, atomic archived-session control events, and honest realtime recovery
  wording.
- PR #414 reconciled the public planning surface with those merged facts.
- PR #415 added authenticated, short-lived TURN fallback, bounded WSS
  candidate proofing, current transport-capability ownership, and call-launch
  lifetime fixes. It did not add wire fields, persisted state, a schema
  migration, or a cryptographic-format change.

## Production operations

- The durable relay queue is deployed. Accepted encrypted envelopes survive a
  relay process or container restart.
- The completed `RELAY_ENABLE_HEARTBEAT_ECHO` diagnostic is disabled in
  production.
- A dedicated coturn service is available at `turn.phntm.pro`. The application
  receives expiring credentials through its authenticated relay session; the
  operator secret remains server-side.

## Field validation

- A signed release APK sustained a 6m18s call from a physical phone on LTE/Yota
  to an emulator on Wi-Fi.
- The phone used a TURN relay candidate and the emulator used a relayed peer
  path. Audio was intelligible in both directions, and hangup released the call
  cleanly.
- The phone side had intermittent crackle. This run cannot separate phone audio
  behavior from emulator/host routing or acoustic feedback, so it is not an
  audio-quality acceptance result.

## In progress

- Android design parity is being completed in a separate worktree. It is not
  claimed complete here.
- Call validation still requires two physical phones on independent networks,
  a wider lifecycle matrix, and an evidence-backed resolution of the crackle.
- First-contact latency, public-Alpha group reliability, encrypted attachments,
  and receiver-side voice-download cancellation remain open work.

## Presentation-candidate gates

1. Integrate the design work without weakening the release baseline.
2. Repeat the call matrix on two physical phones and resolve or bound the audio
   crackle with clean recordings and route evidence.
3. Run the expanded two-device smoke for text, voice notes, privacy-mode
   switching, network/process recovery, and calls.
4. Build and verify the final signed APK/AAB, clean-install both physical test
   targets, and rehearse the exact presentation path.

## Honest boundaries

- The current release surface is one-to-one text and voice notes. Groups and
  calls are not represented as production-ready.
- Direct ICE remains preferred; TURN is a fallback and necessarily observes
  endpoint IP addresses, timing, and relayed traffic volume, while WebRTC media
  content remains protected by DTLS-SRTP.
- Tor remains text-only, and REST polling cannot carry realtime media.
- The custom protocol composition has not received an independent external
  cryptographic audit.
- Passing tests and field runs establish the named configurations and dates,
  not every Android device, carrier, NAT, or future filtering policy.
